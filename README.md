# videoSample

Google Flow(Veo 3.1 Lite) + 나노바나나(Nano Banana) 참조 이미지를 활용해
캐릭터 기반 세로형(9:16) 스토리 영상을 8초 단위로 이어 붙여 제작하는 프로젝트.

## 캐릭터
나노바나나로 생성된 캐릭터. Flow 프로젝트 내 참조 이미지로 업로드되어 있으며, 아래는 첨부된 캐릭터 시트(정면 + 턴어라운드 4방향) 기반 시각 특징.

- **공통 스타일**: 3D 픽사풍 렌더의 통통하고 복슬복슬한(fluffy) 아기 펭귄. 진한 남색-회색 머리/등, 크림색 얼굴·배, 오렌지색 부리, 크고 동그란 갈색 눈(캐치라이트 있음), 짧은 회색 물갈퀴 발/날개. 베이지톤 스튜디오 배경, 부드러운 그림자.
- **팽창수**: 장식 없는 기본형. 성별 중립적 귀여운 외형.
- **팽미순**: 정수리 왼쪽(정면 기준 시청자 왼쪽 눈 위쪽)에 **분홍색 벚꽃 모양 머리핀** 착용. 이 머리핀이 팽창수와의 유일한 구분 포인트이며, 그 외 체형/색감/질감은 동일.
- 나노바나나 프롬프트 작성 시 매번 "fluffy 3D pixar-style baby penguin character"와 팽미순의 경우 "small pink cherry-blossom hairpin above left eye" 키워드를 포함해 일관성 강화.
- **관계**: 팽창수 ❤️ 팽미순 = **부부**. 두 캐릭터가 함께 등장하는 씬에서는 부부(연인) 관계임을 감안한 상호작용(다정함, 스킨십, 눈맞춤 등)으로 연출.

## 제작 워크플로우
1. 대화로 8초 분량 씬의 주제/스토리 비트를 정함.
2. 씬마다 **시작 프레임(Start Frame) / 끝 프레임(End Frame)** 나노바나나 프롬프트를 각각 작성.
   - 나노바나나는 프로젝트에 업로드된 캐릭터 이미지를 참조 이미지로 사용.
   - 끝 프레임은 다음 씬의 시작 프레임과 자연스럽게 이어지도록 구도/포즈/배경을 설계.
   - **캐릭터 인식 원리**: 모델은 "팽창수/팽미순"이라는 이름 텍스트를 이해하는 게 아니라 **실제로 첨부한 참조 이미지 파일**을 보고 인식함. 1명만 등장하는 씬은 해당 캐릭터 참조 이미지 1장만 첨부하면 됨. 2명이 함께 등장해 참조 이미지 2장을 동시에 첨부해야 할 때는, 이름 대신 **외형 구분 문구**(예: "no accessory" / "wearing a small pink cherry-blossom hairpin")로 어느 이미지가 누구인지 설명해야 함. 프롬프트 속 이름은 사람이 보기 위한 라벨일 뿐, 모델 인식에는 관여하지 않음.
   - **배경 일치 문제 방지**: 끝 프레임 생성 시 캐릭터 참조 이미지만 첨부하면 배경이 매번 새로 그려져 시작 프레임과 달라질 수 있음. 반드시 **방금 생성된 시작 프레임 이미지 자체도 두 번째 참조 이미지로 함께 첨부**하고, 프롬프트도 "새로 그려줘"가 아니라 "이 시작 프레임 사진을 그대로 베이스로 두고 캐릭터 포즈/상태만 수정해줘"라는 편집 톤으로 작성.
3. 프롬프트 전달 전 **검증 체크리스트**로 자체 점검 후 사용자에게 전달.
   - **첨부 이미지 안내는 필요할 때만**: 매번 기계적으로 안내하지 말고, 헷갈릴 여지가 있는지 판단해서 필요할 때만 명시할 것. 특히 베이스로 쓸 이미지가 여러 버전 중 특정 버전(예: "v5 결과물"처럼 최신 결과물이 아닌 특정 시도)이거나, 참조 이미지가 2장 이상으로 늘어나 순서/조합이 헷갈릴 수 있는 경우에는 반드시 명시. 캐릭터 1장만 쓰는 단순한 경우처럼 자명한 때는 생략 가능.
4. 사용자가 Flow(나노바나나)에서 시작/끝 프레임 이미지 생성 → Veo 3.1 Lite로 8초 영상 생성.
5. 여러 8초 클립을 이어 붙여 총 32~64초 세로(9:16) 스토리 영상 완성.

## 스토리 씬 목록

### Scene 1 (0~8초) — "분리수거 한 번에 다 들고 나가기" [프롬프트 초안 완료, Flow 결과 대기 → 상세: `scenes/scene-01.md`]
- **장르/톤**: 일상 공감 개그
- **등장**: 팽창수 단독 (팽미순 미등장)
- **배경**: 평범한 신혼집 현관
- **상황**: 남편이 재활용품(분리수거)을 한 번에 다 들고 나가려는 모습. "남편들은 왜 분리수거를 한 번에 다 버리려고 할까"라는 공감 포인트 겨냥.
- **과장 수준**: 현실적으로 조금 많은 정도 (몸집보다 큰 산더미까지는 아님)
- **결말**: 씬 자체 완결형 — 균형이 위태로워 휘청이지만 결국 넘어뜨리거나 쏟지 않고 힘겹게 문밖으로 잘 들고 나가는 데 성공하는 모습으로 마무리. ("위태로움 → 다음 씬에서 쏟아짐"이 아니라, "위태로움 → 이 씬 안에서 힘겹게 성공"이 공감 포인트.)
- **미정 사항** (프롬프트 작성 시 자동 제안 예정): 구체적 재활용품 구성, 현관 배경 디테일 수준, 남편 표정/포즈

## 제작 가이드라인 (모든 씬 공통)
- **표정 과장 금지**: 표정은 항상 자연스러운 강도로. 과장된 만화적 리액션(눈알 튀어나옴, 입 쩍 벌어짐 등) 지양, 잔잔하고 현실적인 감정 표현 유지.
- **소품 일관성**: 한 씬 내에서 등장하는 소품(재활용품 종류/개수 등)은 시작 프레임과 끝 프레임에서 반드시 동일하게 유지. 씬 진행 중 소품이 늘거나 줄거나 바뀌면 안 됨(단, 손에 들었다/내려놨다 같은 위치·자세 변화는 가능).
- **미정 디테일 자동 보완 시 원칙**: 사용자가 정해주지 않은 디테일(배경 소품, 표정 세기 등)을 임의로 채울 때는 항상 "영상의 자연스러움"을 최우선 기준으로 판단. 튀거나 부자연스러운 요소보다는 평범하고 개연성 있는 선택 우선.
- **외형 임의 변경 금지**: 캐릭터의 비율·색감·털 질감·생김새는 참조 이미지와 완전히 동일하게 유지. 나노바나나가 임의로 외형을 바꾸지 않도록 프롬프트에 명시.
- **의상 임의 추가 금지**: 사용자가 명시적으로 요청하지 않는 한 캐릭터에 옷/의상/코스튬을 입히지 않음. 참조 이미지처럼 맨몸 상태 유지가 기본값.
- **FACE LOCK 블록 필수**: "외형 바꾸지 마"처럼 추상적인 금지 문구만으로는 나노바나나가 잘 안 지킴(포즈가 바뀌는 장면일수록 얼굴도 같이 다시 그리며 눈썹 등 디폴트 디테일을 붙이는 경향 있음). 매 프롬프트에 **구체적인 얼굴 특징 고정 문구**를 포함할 것: "NO eyebrows"처럼 없어야 할 것을 명시, 눈 크기/모양/비율을 구체적으로 재기술. 표정 묘사에 "brow", "furrow"처럼 눈썹을 연상시키는 단어는 쓰지 않기(팽창수/팽미순은 눈썹이 없는 디자인).
- **끝 프레임은 "변화 요청"을 최상단에 강조**: 시작 프레임을 베이스로 편집할 때 "배경/구도는 유지하고 캐릭터만 살짝 바꿔라" 식으로 "유지"를 먼저 말하면 모델이 유지 쪽에 치우쳐서 요청한 변화(문 열림, 이동, 자세 변화 등)를 거의 반영 안 하는 경우가 있음. 프롬프트 맨 위에 **"REQUIRED CHANGES" 리스트**로 반드시 달라져야 할 부분을 명확히 못박고, "이건 베이스와 거의 동일한 반복이 아니다"라고 명시한 뒤, 그 다음에 "유지할 것" 목록을 배치할 것.
- **"제자리에서 위치 이동"은 잘 안 먹힘, 그렇다고 줌인으로 때우지 말 것**: "같은 구도 유지 + 캐릭터만 앞으로 이동" 요청은 반복적으로 실패함(문 열기처럼 국소적 변화는 반영되지만, 인물이 프레임 내에서 이동하는 건 거의 무시됨). "카메라를 고정하고 인물만 확대"하는 줌인 트릭은 기술적으로는 더 잘 먹히지만, **실제 이동이 아니라 카메라 트릭이라 "나간다/걸어간다" 같은 서사와 안 맞을 수 있음** — 이 프로젝트에서는 사용자가 이 접근을 반려함. 줌인 트릭은 정말 막다른 경우의 최후 수단으로만 고려.
- **씬을 짤 때 카메라-캐릭터-목적지의 물리적 배치를 먼저 점검할 것**: 문/목적지가 캐릭터 뒤(배경)에 있는 구도라면, 그쪽으로 이동한다는 건 카메라에서 멀어지며 몸을 돌려 **뒷모습**을 보이는 게 물리적으로 맞음. "정면을 유지한 채 목적지 쪽으로 전진"은 실제로는 뒷걸음질을 요구하는 모순된 지시가 될 수 있음. 이런 경우 끝 프레임을 아예 뒷모습으로 설계하면 (a) 물리적으로도 자연스럽고 (b) "멀어지며 작아짐"이 줌인처럼 눈속임이 아닌 정당한 원근 변화가 되고 (c) FACE LOCK 문제도 사라짐(얼굴이 안 보이므로). 씬 기획 단계에서 캐릭터의 이동 방향과 카메라 위치를 먼저 그려보고 정면 유지가 가능한 동선인지 확인할 것.
- **영상 프롬프트(Veo 3.1 Lite)는 다단계 동작을 한 번에 요청하면 실패하기 쉬움**: "문 열기 + 뒤돌기 + 걷기 + 휘청임 + 멈추기"처럼 여러 단계를 한 번에 요청하면, Lite 모델이 8초 안에 상태(문 열림 유지, 소품 지속성, 실제 이동)를 안정적으로 못 지키고 제자리에서 동작을 반복/왕복하는 경우가 있었음(문이 열렸다 닫혔다 반복, 제자리걸음, 소품이 깜빡이며 사라짐/재등장). **대응**: (1) 영상 생성 후 반드시 2fps 정도로 프레임을 뽑아 직접 검증할 것(Bash로 ffmpeg/imageio-ffmpeg 이용). (2) 프롬프트에 "CRITICAL RULES" 같은 절대 금지 목록을 넣어 "문은 한 번 열리면 계속 열려있어야 한다", "캐릭터는 매 순간 전진해야 하며 제자리걸음/후퇴 금지", "소품은 계속 보여야 하며 깜빡이면 안 됨", "동작을 반복/역행하지 말 것"을 명시. (3) 그래도 안 되면 요청 동작 자체를 더 단순화(단계 수를 줄이는 것)를 고려.
- **끝 프레임의 "도착점"은 애매하게 잡지 말 것**: 끝 프레임이 이미지 자체로는 검증 체크리스트를 통과해도(배경/소품/자세 일관성 등), 그게 "거의 도착" 수준(예: 문턱 근처)이면 실제 Veo 영상 생성 시 모델이 그 애매한 지점까지도 제대로 못 이어가고 헤맬 수 있음(문 열림/닫힘 반복, 제자리걸음 등). 끝 프레임은 **명확하게 완료된 상태**(예: 완전히 문 밖으로 나가 바깥에 선 모습)로 설계할 것. 이미지 프레임 검증 통과와 실제 영상화 성공은 별개이므로, **영상 결과까지 확인한 뒤에** 프레임을 "최종 확정"으로 기록할 것.
- **캐릭터가 뒤돈다(180도 회전)는 건 소품/손의 화면 좌우도 같이 바뀌어야 함**: 정면일 때 화면 왼쪽에 있던 소품(오른쪽 날개에 든 것)은, 캐릭터가 뒤돌면 화면 오른쪽으로 위치가 바뀌는 게 물리적으로 맞음(반대도 마찬가지). 나노바나나는 이걸 자동으로 계산하지 않고 화면 좌우를 그대로 복사하는 경향이 있어서, 결과적으로 팔이 꼬이거나 소품이 순간이동한 것처럼 보이는 오류가 생김. **뒤돈 이후 프레임을 만들 때는 각 소품이 화면상 어느 쪽에 있어야 하는지 명시적으로 지정할 것**(예: "정면일 때 화면 왼쪽에 있던 A 소품은 뒤돈 뒤 화면 오른쪽에 있어야 한다").
- **틀린 결과물을 베이스로 "이 부분만 고쳐라"는 잘 안 먹힘 → 마지막 올바른 베이스로 되돌려서 처음부터 다시 생성**: 이미지에 오류가 있어서(예: 소품 좌우 오류) 그 이미지를 베이스로 교정 지시를 줘도, 모델이 베이스 이미지의 기존 레이아웃에 강하게 앵커링되어 텍스트 교정을 무시하는 경우가 많음(앞서 "제자리 이동" 실패 패턴과 동일). 오류가 발견되면 **그 오류가 없던 마지막 확인된 이미지(예: 시작 프레임)로 베이스를 되돌리고, 그 지점부터 모든 필요한 변화(이동+교정 등)를 한 번에 새로 생성**하는 게 더 효과적. "틀린 걸 고쳐가는" 체인을 길게 이어가지 말 것.
- **좌우 반전(뒤돌기)은 나노바나나의 구조적 약점일 수 있음**: 베이스 이미지를 바꿔가며(틀린 결과물 기반, 시작 프레임 기반 등) 3번 연속 시도해도 소품 좌우가 전혀 안 바뀐 사례 있음. "물리적으로 왜 바뀌어야 하는지" 설명하는 방식이 안 통하면, "미러/좌우반전(flip)"이라는 순수 이미지 편집 개념으로 바꿔서 시도해볼 것. 그래도 안 되면 **이건 모델 한계로 보고 포기하는 것도 현실적 선택** — 숏폼 영상에서 시청자가 눈치채기 어려운 디테일이라 완벽을 고집하기보다 더 중요한 문제(예: 캐릭터가 충분히 이동했는지)에 시간을 쓰는 게 나을 수 있음.

## 프롬프트 검증 체크리스트
- 캐릭터 일관성: 이름/외형 특징(팽미순 분홍 머리핀 등) 명시 여부

- 소품 일관성: 시작/끝 프레임에서 재활용품 등 소품 종류·개수가 동일한지
- 표정 과장 여부: 자연스러운 감정 표현인지, 과장되지 않았는지

- 9:16 세로 구도 명시 여부
